# Code of Conduct

## Our Standard

MediCore is intended to be a professional, technical, and respectful software project.

We expect everyone participating in the project to communicate professionally and to focus discussions on improving the software.

Contributors, maintainers, issue reporters, reviewers, and other participants are expected to:

- communicate respectfully;
- assume good faith unless there is clear evidence otherwise;
- provide constructive technical feedback;
- explain disagreements with technical reasoning;
- accept that different approaches can have legitimate trade-offs;
- respect different levels of experience;
- avoid personal attacks;
- keep discussions relevant to the project;
- protect private and sensitive information.

---

# Unacceptable Behavior

The following behavior is not acceptable:

- harassment or discrimination;
- personal attacks;
- threats or intimidation;
- deliberately disruptive behavior;
- insulting or humiliating other contributors;
- publishing private information without permission;
- sharing credentials, tokens, or sensitive user information;
- deliberately exposing private medical information;
- sexual harassment or unwanted sexual attention;
- hate speech;
- trolling intended to disrupt project discussion;
- repeated off-topic disruption;
- intentionally submitting malicious code or vulnerabilities through normal contribution channels.

Technical disagreement is allowed.

Personal attacks are not.

---

# Technical Disagreements

MediCore involves decisions around:

- machine learning;
- RAG architecture;
- databases;
- security;
- authentication;
- frontend architecture;
- infrastructure;
- medical safety.

Reasonable disagreement is expected.

When disagreeing:

1. Explain the problem.
2. Provide technical evidence where possible.
3. Identify trade-offs.
4. Propose an alternative.
5. Keep the discussion focused on the implementation rather than the person.

Maintainers may close discussions when they become repetitive or unproductive.

---

# Security and Privacy

Do not post the following publicly:

- API keys;
- passwords;
- authentication tokens;
- database credentials;
- private user information;
- real patient or medical information;
- private production logs;
- confidential infrastructure details.

Security vulnerabilities should be reported according to `SECURITY.md`.

---

# Medical Content

MediCore is a medical information application, so discussions involving medical behavior should remain evidence-oriented and technically responsible.

Do not intentionally introduce misleading medical information into the project.

If a contributor identifies potentially unsafe model behavior, raise it through the appropriate issue or security process rather than attempting to conceal the behavior.

---

# Enforcement

Maintainers are responsible for keeping project discussions professional.

Depending on the severity and frequency of behavior, maintainers may:

1. request that the behavior stop;
2. remove inappropriate comments;
3. close an issue or pull request;
4. restrict participation;
5. remove a contributor from the project;
6. report serious threats or unlawful conduct to the appropriate authorities where necessary.

Actions will be based on the behavior and available evidence.

# Scope

This Code of Conduct applies to:

- GitHub issues;
- pull requests;
- code reviews;
- repository discussions;
- project documentation;
- other project spaces operated by the maintainers.

It also applies when someone is representing the project in a public or professional setting.

---

# Final Principle

The goal is simple:

**Build good software, discuss technical decisions honestly, and treat the people working on the project with respect.**
